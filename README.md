# Looprun

Run a loop, fill the map. An Android-first running game on a shared city map built on H3 hex cells.
The phone records GPS and shows the map; the server decides loops, cell ownership and cheating.

Flutter app (Android first). The backend (engine, API, worker, deployment) is in a separate repository:
**https://github.com/VivekMakwana24/looprun-backend**. The API contract is owned there
(`docs/CONTRACT.openapi.yaml`); this repo keeps a snapshot at `docs/api/CONTRACT.openapi.yaml` with the commit it was copied from.

> Status: first compiled and tested by GitHub CI (see `NOTES.md`, "Unverified APIs", and `docs/verification/`).

## Run against the backend

1. Start the backend: `git clone https://github.com/VivekMakwana24/looprun-backend && cd looprun-backend && docker compose up --build`
   (API on `http://127.0.0.1:8000`, dev auth on).
2. Run the app against it (Android emulator reaches the host at `10.0.2.2`):

```bash
bash tool/bootstrap.sh && flutter pub get && dart run build_runner build --delete-conflicting-outputs
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000 --dart-define=DEV_AUTH=true
```

## Build

Requires Flutter stable 3.47.x (Dart 3.12+), JDK 21 (maplibre_gl needs it), Android SDK.

```bash
bash tool/bootstrap.sh            # flutter create (android scaffold) + our manifest + patches
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # Drift generates lib/data/db/app_database.g.dart
flutter analyze --no-fatal-infos
flutter test
flutter build apk --debug \
  --dart-define=API_BASE_URL=https://api.example.com \
  --dart-define=GOOGLE_SERVER_CLIENT_ID=<web client id>.apps.googleusercontent.com
```

The dev login button needs a backend started with `LOOPRUN_DEV_AUTH=1` (the backend repo's dev compose file does that).

## --dart-define options

| Name | Default | Meaning |
| --- | --- | --- |
| `API_BASE_URL` | `http://10.0.2.2:8000` | Backend origin ([looprun-backend](https://github.com/VivekMakwana24/looprun-backend)); `/v1` is appended |
| `DEV_AUTH` | `false` | Shows the dev login (`id_token = "dev:<name>"`) on the sign-in screen |
| `GOOGLE_SERVER_CLIENT_ID` | empty | Web OAuth client id, so Google returns an ID token the server can verify |
| `MAP_TILE_PROVIDER` | placeholder | Name shown in the location disclosure (must be real in release) |
| `PRIVACY_POLICY_URL` | placeholder | URL shown in the location disclosure (must be real in release) |
| `MAP_STYLE_URL` | MapLibre demo tiles | MapLibre style JSON URL |

Google sign-in on Android also needs an OAuth client of type Android (package `app.looprun.looprun`
plus the signing key SHA-1) in the same Google Cloud project. That is console configuration, not code.

## Layout

See `docs/MOBILE_ARCHITECTURE.md` for the rules. In short:

```
lib/core/          config, theme, formatting, AppException
lib/domain/recorder/ pure Dart: run state machine, GPS health, haversine
lib/data/          providers.dart (DI), services/, db/, repositories/, models/, upload/
lib/ui/            one folder per feature: *_screen.dart (view) + *_view_model.dart (Riverpod notifier)
lib/router.dart    go_router + appRedirect (signed out -> sign-in, no disclosure -> disclosure, else home)
test/              fakes/, domain/, data/, ui/, architecture_test.dart
tool/              bootstrap.sh, patch_android.sh, patch_signing.sh, check_manifest.sh
android/           only app/src/main/AndroidManifest.xml is ours; the rest is generated by bootstrap.sh
```

## Release

`.github/workflows/release-android.yml` (manual) builds a signed AAB. It needs these secrets (Settings > Secrets and variables > Actions):
`ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_PASSWORD`, `ANDROID_KEY_ALIAS`; and these variables:
`API_BASE_URL` (https, the deployed backend), `GOOGLE_SERVER_CLIENT_ID`, `MAP_STYLE_URL`, `MAP_TILE_PROVIDER`, `PRIVACY_POLICY_URL`.
The job fails on empty or placeholder values. Create the upload keystore once on your machine and never commit it:

```bash
keytool -genkeypair -v -keystore upload-keystore.jks -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 -alias upload
base64 -w0 upload-keystore.jks > upload-keystore.b64
```

`tool/patch_signing.sh` injects the release signing config into the generated `android/app/build.gradle.kts`; the workflow verifies the AAB
with `jarsigner`, checks `targetSdkVersion >= 36`, and uploads it as the artifact `looprun-release-aab`. Bump `version:` in `pubspec.yaml`
before each upload. Upload the AAB in the Play Console yourself (closed test: `docs/compliance/closed-test-checklist.md`). Use Play App Signing.
Backend deployment and its secrets are documented in looprun-backend (`docs/RUNBOOK.md`).

## CI

`.github/workflows/ci.yml` runs on every push and PR:

`bootstrap.sh` -> `flutter pub get` -> `build_runner build` -> `flutter analyze --no-fatal-infos` -> `flutter test` -> `flutter build apk --debug` -> `tool/check_manifest.sh` (fails if the merged manifest requests ACCESS_BACKGROUND_LOCATION).
