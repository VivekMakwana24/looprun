## Verifier's scratch tests against the new code
`pytest test_v2_delete.py test_v2_locks.py test_v2_freeze_lb.py test_v2_residue.py test_v2_claims.py` in the verifier's directory:
48 passed, 3 failed. The three are tests whose expectation is the old behaviour, not defects:
- `test_upload_racing_delete_leaves_orphan_run` expects HTTP 202 for the stale-token upload; the server now answers 401 and leaves nothing behind (the test's own other assertion, run and fixes gone, holds).
- `test_first_lock_expires_while_waiting_for_second_and_nobody_notices`: the intruder can no longer take k1 (the watchdog keeps it alive), so the scripted intruder step never succeeds and the set times out on k2 as it should.
- `test_run_claims_never_cleaned_for_accepted_runs`: asserts `n == 0` after printing a sample of the first document; with zero plans left the print itself raises (`find_one` returns None). The assertion it wanted holds.
