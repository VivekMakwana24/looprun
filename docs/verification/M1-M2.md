### NOTE

- N1. Merged manifest will also carry from flutter_foreground_task: `RECEIVE_BOOT_COMPLETED`, an exported `RebootReceiver`, `RestartReceiver` (autoRunOnBoot is false). Play data/FGS declaration should know; optionally strip with `tools:node="remove"`.
- N2. Upload polling: no cap on how long a job may stay `processing`; after 12 failed polls a job whose upload already succeeded is shown as failed (re-upload is idempotent, so "Try again" is safe). 429 `Retry-After` is ignored (`backoff.dart` uses its own schedule). Runs over 20000 fixes get 413 and fail (documented in NOTES). Local runs are not scoped to the signed-in user; another account on the same phone would get 409 and "failed".
- N3. `RunUiState.path` is copied on every fix (`List.of(...)..add`): O(n^2) over a long run; fine at 1 Hz for hours, worth a ring buffer later.
- N4. `HomeScreen` builds `pages[_index]`, so the MapLibre platform view is destroyed and recreated on each tab switch and `_centerOnMe` re-reads GPS each time; use `IndexedStack` or `AutomaticKeepAlive` if that is not wanted.
- N5. Upload retries run only while `HomeScreen` is mounted (ticker watched there). Retries survive restart (state in Drift) but not an app that is never opened again. Acceptable for MVP; say so in tester guide.
- N6. `describeFlag` covers all engine flag codes (mock_location, teleport, vehicle_speed, implausible_loop, too_few_fixes, near_closure_repaired, loop_rejected_small/large) - checked against `engine/looprun_engine`.
- N7. Cell circle radius is in screen pixels (documented). Fine for the MVP.
- N8. maplibre_gl 0.28 notes: tile provider default `demotiles.maplibre.org` is blocked in release by the workflow (good).

## 7. Layout versus `docs/MOBILE_ARCHITECTURE.md` and refactor steps

1. UI imports data directly: `run_screen.dart`, `run_result_screen.dart`, `home_screen.dart` (`databaseProvider`, `AppDatabase`, `RunRow`), `profile_screen.dart` (`databaseProvider.wipe()`, `Geolocator`), `map_screen.dart` (`Geolocator`, `apiClientProvider`).
